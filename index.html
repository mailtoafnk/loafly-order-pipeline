Python data pipeline

Loafly Pipeline Refactor

A one-file nightly script for an online bakery, rebuilt as a small Python package. It cleans the day's order prices, skips bad rows instead of crashing, retries the flaky orders API, and keeps the API key out of the code. Standard library only.

Python 3.14stdlib only6 modules + runner32 rows · 15 orders

Before and after

legacy_orders.py

loafly/ package

How it runs

run_pipeline.py calls three stages in order

Extract

loafly/extract.py

Reads raw_orders.csv into a list of rows. The file path comes from config.

Transform

loafly/transform.py

Cleans each price inside try / except / else / finally and groups rows into Order objects.

Load

loafly/load.py

Applies the discount and saves each order through gateway.py, with retry.

loafly/config.pyOne SETTINGS dict plus the API key from the environment.
loafly/models.pyThe Order class: add_item() and total().
gateway.pyProvided API client. Fails about 30% of the time. Not edited.

Design decisions

Why it is built this way

Catching ValueError, not just TypeError

A blank CSV cell arrives as "", and float("") raises ValueError. Catching only TypeError and AttributeError would still crash, so all three are caught.

finally counts every row

The finally block runs for good and bad rows alike, which is how the log can report "Checked 32 items" alongside "skipped 3".

Retry without a wasted wait

Each failure logs a WARNING and waits retry_wait_seconds, except after the last attempt. Giving up is an ERROR, and the loop moves on to the next order.

A 10-line .env reader

With no third-party packages allowed, config.py copies KEY=value lines from .env into the environment, then os.getenv reads the key. Only its last 4 characters are ever logged.
